🛠️ Creating & Handling Promises

A Promise represents a value that may be available now, in the future, or never. Use `.then()` for success and `.catch()` for errors.

138_Create_Promise.js 
let order = new Promise(function(resolve, reject) {
    let foodReady = true;
    if (foodReady) resolve("Pizza delivered!");
    else reject("Order cancelled");
});

order.then(function(data) {
    console.log(data); // Success path
}).catch(function(error) {
    console.log(error); // Error path
}).finally(function() {
    console.log("Always executes!");
});

🔗 Promise Chaining

To avoid callback hell, Promises can be chained. Returning a value (or a new Promise) inside a `.then()` passes it to the next `.then()`.

139_Real_Promise_API.js 
openBrowser()
    .then(function(msg) {
        console.log("Step 1:", msg);
        return goToLogin(); // Returns next promise
    })
    .then(function(msg) {
        console.log("Step 2:", msg);
    })
    .catch(function(err) {
        console.log("Fails fast if any step rejects", err);
    });

🚀 Promise.all (Fail-Fast)

Takes an array of Promises and resolves ONLY when all of them resolve. If a single Promise rejects, the entire `Promise.all` immediately rejects.

143_Promise_All.js 
let checks = [
    Promise.resolve("Auth OK"),
    Promise.reject("DB DOWN"),
    Promise.resolve("Cache OK")
];

// This will trigger the .catch block!
Promise.all(checks)
    .then(function(r) { console.log(r); })
    .catch(function(err) { console.log("Failed:", err); });

📊 Promise.allSettled (Test Reports)

Unlike `all()`, `allSettled()` waits for all Promises to finish, regardless of success or failure. Perfect for generating complete test reports.

144_Promise_Settle.js 
Promise.allSettled([
    Promise.resolve("Test A Passed"),
    Promise.reject("Test B Failed")
]).then(function(results) {
    results.forEach(function(r) {
        if(r.status === "fulfilled") {
            console.log("PASS: " + r.value);
        } else {
            console.log("FAIL: " + r.reason);
        }
    });
});
Zero to Hero

Interview Preparation

Q1: What is the difference between `Promise.all()` and `Promise.allSettled()`?
`Promise.all()` is "fail-fast". It rejects immediately if *any* of the promises reject. `Promise.allSettled()` waits for all promises to finish (either resolve or reject) and returns an array containing the status of each promise. It never rejects on its own.
Q2: How does `Promise.race()` work?
`Promise.race()` takes an array of promises and resolves/rejects as soon as the **first** promise settles (either successfully or with an error). It's a literal race. A common use case is implementing timeout limits on API calls.
Q3: Will the `.catch()` block run if an error occurs in a `.finally()` block?
No! The `.finally()` block runs *after* the promise settles. If an error is thrown inside `.finally()`, it will not be caught by the `.catch()` that comes before it. The new error must be caught downstream or it will become an unhandled promise rejection.
Q4: What happens if you don't return anything inside a `.then()`?
If you don't explicitly return a value inside a `.then()` block, it implicitly returns `undefined`. The next `.then()` in the chain will receive `undefined` as its argument.

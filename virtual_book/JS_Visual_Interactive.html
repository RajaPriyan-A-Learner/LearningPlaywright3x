Topic 01
Callbacks
The original JavaScript async pattern. A function you hand over to another function to call when it's done. Simple but riddled with deep problems.

😈 The Problem: Callback Hell

loginUser('raja', 'pass123', (err, user) => { if (err) throw err; fetchProfile(user.id, (err, profile) => { if (err) throw err; fetchPermissions(profile.role, (err, perms) => { if (err) throw err; loadDashboard(perms, (err, dash) => { if (err) throw err; console.log(dash); // 😭 Finally! }); }); }); }); });

🔬 Deep Insights

🔄
Inversion of Control
When you pass a callback to a 3rd-party library, you trust it to call your function exactly once, at the right time, with the right arguments. If the library has a bug, your payment callback could fire twice. You lose all control.
🧩
Trust Issues
Callbacks have 5 trust problems: too early, too late, too many times, too few times, or swallowing errors. Every single one of these requires defensive code that bloats every callback you write.

Topic 02
new Promise
A Promise is a state machine — a guaranteed single-transition object that flows from Pending → Fulfilled or Pending → Rejected. Its state is immutable once settled.
⏳ PENDING
resolve()
reject()
✅ FULFILLED .then()
❌ REJECTED .catch()
javascript
const myPromise = new Promise((resolve, reject) => {
  // ⚠️ This executor runs SYNCHRONOUSLY, immediately!
  const success = Math.random() > 0.5;

  setTimeout(() => {
    if (success)
      resolve({ id: 42, name: "Raja" });  // Pending → Fulfilled
    else
      reject(new Error("Network Failure")); // Pending → Rejected
  }, 2000);
});

myPromise
  .then(data => console.log("✅ Got:", data))
  .catch(err => console.error("❌ Err:", err.message))
  .finally(() => console.log("🏁 Done"));

Topic 04
Promise.race()
The first Promise to settle wins. Losers are silently ignored — but not cancelled! This is the key pattern for implementing network timeouts.
// Click to race...
javascript — Real-World Timeout Pattern
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`Timed out after ${ms}ms`)), ms)
  );
  return Promise.race([promise, timeout]);
}

// Usage — fails fast if API takes more than 3 seconds
const result = await withTimeout(fetch('/api/data'), 3000);

⚡
async function = Promise Factory
Every async function always returns a Promise. return "hello" becomes return Promise.resolve("hello"). You can never get a raw value out of one from synchronous code.
⏸️
await suspends the function, NOT the thread
await pauses the local async function's execution and yields control back to the caller. The rest of the JavaScript program keeps running. This is why D prints before C.
⚠️
The forEach Trap
await inside .forEach() does not work sequentially. forEach is not Promise-aware. Use for...of for sequential, Promise.all for parallel.
🛡️
try/catch catches both sync & async errors
A single try/catch wrapping await calls handles both runtime synchronous errors AND asynchronous Promise rejections. This is impossible with raw .catch().
🏎️
Sequential vs Parallel Await
Two sequential awaits = time of A + time of B. Promise.all([A, B]) = time of the slowest one. For independent operations, always prefer parallel.
🎭
Top-Level Await (Modern JS)
In ES Modules, you can now use await directly at the root of a script without wrapping it in an async IIFE. This simplifies module initialization but can block the entire module loading chain.

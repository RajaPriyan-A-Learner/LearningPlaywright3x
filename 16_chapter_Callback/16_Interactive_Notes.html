Mastering Callbacks

Understand asynchronous execution and how to handle data flowing through higher-order functions without falling into Callback Hell.

Deep Insights

Core Concepts Extracted

🔄 Synchronous Callbacks

A callback passed to a function that executes immediately and synchronously, blocking the main thread. Common in Array iteration methods like `.map()` and `.forEach()`.

Sync Callback
function greet(name, callback) {
    console.log("Hello " + name);
    callback(); // Executes immediately
}
greet("Raja", function() { 
    console.log("Callback done!"); 
});

⏳ Asynchronous Callbacks

Executed after an asynchronous operation completes. Essential for non-blocking I/O operations (Timers, API calls, Events). Pushed to the Task Queue.

Async Callback
setTimeout(function() {
    console.log("Executed after 2 seconds");
}, 2000);

⚠️ Loss of 'this' Context

When you pass an object method as a callback, it loses its `this` context because it is executed by a different part of the system (like the window object).

Gotcha Fix
const user = {
    name: "John",
    sayHi() { console.log(this.name); }
};
// undefined!
setTimeout(user.sayHi, 100); 

// Fix: Use arrow function
setTimeout(() => user.sayHi(), 100);

😈 Callback Hell (Pyramid of Doom)

When multiple sequential asynchronous operations are nested deeply inside callbacks, the code expands horizontally and becomes unmaintainable.

Pyramid of Doom
download(function(data) {
    process(data, function(processed) {
        upload(processed, function(result) {
            console.log("Done");
        });
    });
});
Practical Application

Real World & Common Mistakes

🛠️ Real-World Use Case

Event Listeners in the DOM: Callbacks are the foundation of Web UI interactions. Promises resolve only once, so callbacks are mandatory for buttons that can be clicked multiple times.

Practical Example
const btn = document.getElementById("submit");
// The callback runs every time a click occurs
btn.addEventListener("click", function(event) {
    console.log("User submitted form at: ", event.timeStamp);
});

❌ Common Developer Mistake

Executing the callback immediately instead of passing it! Adding parenthesis `()` when passing a callback executes it instantly instead of waiting.

Common Mistake
function showAlert() { alert("Hi!"); }

// MISTAKE: Alerts instantly, passing 'undefined' to setTimeout
setTimeout(showAlert(), 1000); 

// CORRECT: Pass the function reference (no parentheses)
setTimeout(showAlert, 1000);
Zero to Hero

Interview Preparation

Q1: What will print first in this code block?
console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
Answer: A, C, B. Even though the timeout is `0` milliseconds, `setTimeout` pushes the callback to the Task Queue. It must wait until the main Call Stack is empty before executing.
Q2: How do you solve Callback Hell?
By refactoring the code to use Promises, or modern `async/await` syntax, which flattens the execution flow and makes it look synchronous.

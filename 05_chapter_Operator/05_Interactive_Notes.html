Core Concepts Extracted

⚖️ `==` vs `===`

Loose equality (`==`) coerces types before comparing, causing chaotic results (e.g., `"" == 0` is true). Strict equality (`===`) checks both value AND type without any coercion.

Equality Trap
console.log("" == 0);   // true 💥
console.log("0" == 0);  // true 💥
console.log("" == "0"); // false!

// Always prefer ===
console.log("5" === 5); // false ✅

🔄 The Dual Nature of `+`

The `+` operator performs both mathematical addition AND string concatenation. If EITHER side of a `+` is a string, JavaScript converts the other side to a string.

Coercion
console.log(5 + 3);       // 8
console.log("5" + 3);     // "53"

// Evaluates left to right!
console.log(5 + 3 + "x"); // "8x"
console.log("x" + 5 + 3); // "x53"

⚡ Short-Circuit Evaluation

Logical operators don't just return `true` or `false`. `&&` returns the FIRST falsy value. `||` returns the FIRST truthy value. If they find it, they short-circuit and stop evaluating.

Value Returning
// && stops at the first falsy
console.log(1 && 0 && 3); // 0

// || stops at the first truthy
console.log(0 || "A" || false); // "A"

❓ Nullish Coalescing (`??`)

Unlike `||` which treats all 7 falsy values as triggers, the `??` operator ONLY triggers on `null` or `undefined`. Use it when `0`, `""`, or `false` are valid values you want to preserve.

Safe Defaults
let score = 0;

// || Rejects the valid 0 score!
console.log(score || 100); // 100 💥

// ?? Keeps the valid 0 score!
console.log(score ?? 100); // 0 ✅
Practical Application

Real World & Common Mistakes

🛠️ Real-World Use Case

The Ternary Operator (`?:`): Often used to cleanly evaluate an inline expression for UI rendering or template literals, acting as a concise replacement for `if/else` statements.

Practical Example
let role = "admin";

// condition ? ifTrue : ifFalse
let access = role === "admin" ? "Full" : "Deny";

console.log(`Access Level: ${access}`);

❌ Common Developer Mistake

Pre vs Post Increment (`++`): In an expression, `x++` uses the current value THEN increments. `++x` increments FIRST then uses the new value.

Common Mistake
let a = 5;
let b = a++; // Post-increment

// People expect b = 6, a = 6
console.log(b); // 5! (old value used first)
console.log(a); // 6

let c = ++a; // c = 7, a = 7

Interview Preparation

Q1: When would it be acceptable to use `==` instead of `===`?
The only generally accepted exception by style guides (like ESLint) is using `value == null` as a shorthand to check for BOTH `null` and `undefined` in a single stroke (since `null == undefined` evaluates to true).
Q2: What is the output of `"5" - 3` and `"5" + 3`?
`2` and `"53"`. The minus operator ONLY does arithmetic, so it coerces the string "5" into a number. The plus operator prefers string concatenation, so it coerces the number 3 into a string.
Q3: Why shouldn't you nest ternary operators deeply?
Nesting ternary operators more than 2 levels deep becomes incredibly difficult to read and maintain. A bug in nesting order can silently produce wrong results. Use an `if / else if` ladder for complex logic instead.

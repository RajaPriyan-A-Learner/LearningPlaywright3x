Core Concepts Extracted

⚖️ The 7 Falsy Values

JavaScript evaluates conditions based on their boolean truthiness. There are exactly 7 falsy values. Everything else in the language is truthy!

Memorize These
// If it's not one of these 7, it's TRUTHY:
false
0
-0
0n // BigInt zero
"" // Empty string
null
undefined
NaN

🤯 Truthy Surprises

Empty objects and empty arrays are TRUTHY! Even the string `"0"` is truthy because it is a non-empty string. Only `null` and `undefined` represent the true absence of an object.

Truthy Gotchas
if ("0") { console.log("runs"); }
if ([])  { console.log("runs"); }
if ({})  { console.log("runs"); }
if (-1)  { console.log("runs"); }

🪜 The Else-If Ladder

An `else if` ladder checks conditions sequentially from top to bottom. Once a condition evaluates to true, it executes that block and **skips the rest of the entire chain**.

Execution Flow
let score = 85;
if (score >= 90) { /* skipped */ }
else if (score >= 80) { 
    /* RUNS, then exits the ladder! */ 
}
else if (score >= 70) { /* ignored */ }

🚫 The Dangling Else Problem

Omitting curly braces `{}` on single-line `if` statements is technically valid, but it leads to the "Dangling Else" bug where an `else` binds to the wrong inner `if`.

Always Use Braces
if (a > 0)
    if (b > 0)
        console.log("Both");
else
    // ❌ BUG: This else binds to the inner IF!
    console.log("Which one failed?");
Practical Application

Real World & Common Mistakes

🛠️ Real-World Use Case

The Double-Null Guard: In real world data processing, we frequently need to verify that a value actually exists before doing work on it. Using the loose equality `== null` trick is incredibly common.

Practical Example
// Covers both null and undefined in one check!
if (user.profileData == null) {
    console.log("Data is missing or unset");
}

// Compare to strict equality:
if (data === null || data === undefined) { ... }

❌ Common Developer Mistake

Assignment vs Comparison: Using a single `=` inside an `if` condition. This reassigns the variable instantly, and because the assigned value is truthy, the `if` block executes when it shouldn't!

Common Mistake
let status = "pass";

// MISTAKE: Reassigns to "fail", which is truthy
if (status = "fail") {
    console.log("Failed!"); // 💥 Always runs!
}

// CORRECT
if (status === "fail") { ... }
Zero to Hero

Interview Preparation

Q1: Is an empty array `[]` truthy or falsy? What about `{}`?
Both are TRUTHY. In JavaScript, an empty array and an empty object are fully instantiated objects in memory. The only things that represent a true absence of value are `null` and `undefined`.
Q2: What is the difference between a chained `if` block and an `else if` ladder?
Chained `if` blocks evaluate *every single condition* sequentially; multiple blocks can potentially execute. An `else if` ladder evaluates top-to-bottom and stops executing the moment the *first* condition is met.
Q3: Why is it an anti-pattern to check `if (isLoggedIn === true)`?
It is completely redundant. The `if` statement automatically evaluates expressions for truthiness. You can simply write `if (isLoggedIn)`.

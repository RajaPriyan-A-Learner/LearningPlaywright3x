⚖️ The `typeof null` Bug

`typeof null` returns `"object"`. This is a 27-year-old bug! In the original JS implementation, the type tag for an object was `000`, and `null` was all zeros, so they matched. It was never fixed for backward compatibility.

Historical Bug
console.log(typeof null); // "object" ⚠️

// How to correctly check for null:
if (value === null) {
    console.log("This is actually null");
}

🔢 The Universal Number Type

JavaScript has no `int`, `float`, or `double`. All numbers are stored as **IEEE 754 double-precision 64-bit** floating-point numbers. This single type handles everything from `42` to `NaN`.

IEEE 754 Quirks
console.log(typeof 42);      // "number"
console.log(typeof 3.14);    // "number"
console.log(typeof NaN);     // "number"

// The famous floating point rounding error:
console.log(0.1 + 0.2);      // 0.30000000000000004

🫙 `null` vs `undefined`

`undefined` is assigned by JavaScript to mean "not yet assigned". `null` is assigned by Developers to mean "intentional absence of value". They loosely equal each other, but strictly do not.

Empty Values
let a;
console.log(a);              // undefined (JS set it)

let b = null;
console.log(b);              // null (You set it)

console.log(a == b);         // true (Loose equality)
console.log(a === b);        // false (Strict equality)

😵 Not-a-Number (NaN) Is Lonely

`NaN` represents a failed mathematical operation. Uniquely, `NaN` is the ONLY value in JavaScript that is not equal to itself.

NaN Behaviors
console.log(NaN === NaN);    // false!

// Because of this, we MUST use Number.isNaN()
console.log(Number.isNaN(NaN)); // true ✅

// Avoid global isNaN(), as it coerces strings:
console.log(isNaN("hello"));    // true ⚠️
Practical Application

Real World & Common Mistakes

🛠️ Real-World Use Case

Using BigInt: Standard JavaScript numbers lose precision for integers larger than `Number.MAX_SAFE_INTEGER` (2^53 - 1). For massive IDs (like database UUIDs or Twitter Snowflake IDs), we append `n` to create a `BigInt`.

Practical Example
// Precision is lost here:
console.log(9007199254740992 === 9007199254740993); // true 💥

// BigInt maintains perfect precision:
let bigId = 9007199254740992n;
let bigId2 = 9007199254740993n;
console.log(bigId === bigId2); // false ✅

❌ Common Developer Mistake

Trusting `typeof` for Arrays: Developers frequently try to check if a value is an array by using `typeof`. But in JavaScript, an Array is just an object under the hood!

Common Mistake
let list = [1, 2, 3];

// MISTAKE
if (typeof list === "array") {
    // NEVER RUNS! typeof list is "object"
}

// CORRECT
if (Array.isArray(list)) {
    console.log("It's an array!"); // ✅
}
Zero to Hero

Interview Preparation

Q1: Name all the primitive types in JavaScript.
There are 7 primitive types: `string`, `number`, `bigint`, `boolean`, `undefined`, `null`, and `symbol`. Everything else (Arrays, Functions) is considered an `object`.
Q2: What is the difference between global `isNaN()` and `Number.isNaN()`?
Global `isNaN("text")` forces type coercion, converting "text" to NaN, then returning true (which is misleading). `Number.isNaN("text")` does NOT coerce; it only returns true if the value is *literally* NaN. Always prefer `Number.isNaN()`.
Q3: Why doesn't `0.1 + 0.2 === 0.3`?
Because JavaScript numbers are IEEE 754 double-precision floating points. Some decimals cannot be perfectly represented in binary form, leading to microscopic rounding errors (it equals `0.30000000000000004`).

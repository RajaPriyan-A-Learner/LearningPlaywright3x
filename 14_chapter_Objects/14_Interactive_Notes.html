🧩 Object Creation & Access

Key-Value pair collections. Keys with spaces require quotes and bracket notation for access.

Dot vs Bracket Notation
const user = {
    name: "John",
    age: 30,
    "home address": "123 Main St"
};
console.log(user.name); // Dot notation
console.log(user["home address"]); // Bracket

⚠️ Call by Reference

When you assign an Object to a new variable, JS only copies the memory address pointer. Modifying the copy modifies the original!

Reference Trap
let obj1 = { a: 1 }; 
let obj2 = obj1;
obj2.a = 2; 

console.log(obj1.a); // obj1.a is now 2!

🧬 Shallow vs Deep Copy

The spread operator creates a shallow copy (nested objects remain referenced). Use `structuredClone()` for a complete deep copy.

Cloning Data
// Shallow Copy
const shallow = { ...obj };

// Deep Copy (Modern JS)
const deep = structuredClone(obj);

🧊 Object Mutation Locking

Using `const` doesn't prevent mutating properties. To prevent modification, use the built-in `Object` methods.

Freeze vs Seal
// Completely immutable
Object.freeze(obj);

// Cannot add/delete, but can modify existing
Object.seal(obj);
Practical Application

Real World & Common Mistakes

🛠️ Real-World Use Case

State Management & Configurations: Objects are universally used to pass large configuration options to libraries (like fetch options or Webpack configs) or store UI State.

Practical Example
const API_CONFIG = {
    url: "https://api.test.com",
    method: "POST",
    headers: { "Authorization": "Bearer Token" }
};
// Dynamically checking for a header
if (!API_CONFIG.headers["Content-Type"]) {
    API_CONFIG.headers["Content-Type"] = "application/json";
}

❌ Common Developer Mistake

Call By Reference Bug: Copying an object using `=` or even the Spread Operator `{...obj}` creates a Shallow Clone. Nested objects share the same memory!

Common Mistake
let profile = { data: { role: "user" } };

// MISTAKE: Shallow Clone
let adminProfile = { ...profile };
adminProfile.data.role = "admin";
console.log(profile.data.role); // It changed to "admin" too! 💥

// CORRECT: Deep Clone
let safeAdmin = structuredClone(profile);
Zero to Hero

Interview Preparation

Q1: What is the output of this equality check?
const a = { x: 1 };
const b = { x: 1 };
console.log(a === b);
Answer: false. Even though their contents are identical, `a` and `b` point to different locations in memory. `===` compares memory references for objects.
Q2: How do you check if a specific key exists in an object safely?
Using .hasOwnProperty(): obj.hasOwnProperty('name'). This is safer than the in operator because it doesn't check inherited properties from the prototype chain.

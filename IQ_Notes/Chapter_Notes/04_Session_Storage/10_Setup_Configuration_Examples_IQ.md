# Playwright Setup Configurations (Global vs. Project Level)

This document provides sample implementations for both `global-setup.ts` and `auth.setup.ts` (Project setup) and demonstrates how they are wired together in the `playwright.config.ts` file. Finally, it clarifies whether these configurations can be applied at the Test or Suite level.

---

## 1. Global Setup (`global-setup.ts`)
**Scope:** Runs **exactly once** before any tests begin across the entire test run.
**Use Case:** Setting up databases, starting a local server, or performing a single global login (older approach).

```typescript
// global-setup.ts
import { chromium, FullConfig } from '@playwright/test';

// The function must be exported as default
async function globalSetup(config: FullConfig) {
  console.log('--- Running Global Setup ---');
  
  // 1. Manually launch a browser (No fixtures available here)
  const browser = await chromium.launch();
  const page = await browser.newPage();
  
  // 2. Perform global actions (e.g., login)
  await page.goto('https://example.com/login');
  await page.fill('#username', 'admin');
  await page.fill('#password', 'secret');
  await page.click('#login-btn');
  
  // 3. Save the state globally
  await page.context().storageState({ path: 'global-session.json' });
  
  // 4. Important: Always close the browser
  await browser.close();
}

export default globalSetup;
```

---

## 2. Project-Level Setup (`auth.setup.ts`)
**Scope:** Runs as a standard Playwright project, making it easier to utilize fixtures (`page`, `request`, etc.) and Playwright's tracing/reporting capabilities.
**Use Case:** The recommended modern approach for Authentication state generation.

```typescript
// auth.setup.ts
import { test as setup } from '@playwright/test';

setup('authenticate user', async ({ page }) => {
  console.log('--- Running Project-Level Setup (Auth) ---');
  
  await page.goto('https://example.com/login');
  await page.fill('#username', 'user1');
  await page.fill('#password', 'password123');
  await page.click('#login-btn');
  
  // Wait for a successful login indicator
  await page.waitForURL(/.*dashboard/);
  
  // Save storage state to be used by other projects
  await page.context().storageState({ path: 'playwright/.auth/user.json' });
});
```

## 3. Configuration (`playwright.config.ts`)
Here is how you hook both of them up in your main config file:

```typescript
// playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  // ==========================================
  // GLOBAL LEVEL CONFIGURATION
  // ==========================================
  // Points to the global setup file. This runs first.
  globalSetup: require.resolve('./global-setup.ts'),
  
  // If you also had a global teardown, you'd add it here:
  // globalTeardown: require.resolve('./global-teardown.ts'),

  projects: [
    // ==========================================
    // PROJECT LEVEL CONFIGURATION (Setup Project)
    // ==========================================
    {
      name: 'setup',
      testMatch: /.*\.setup\.ts/, // Matches auth.setup.ts
    },
    
    // ==========================================
    // STANDARD PROJECTS (Relying on Setup)
    // ==========================================
    {
      name: 'chromium',
      use: { 
        ...devices['Desktop Chrome'],
        // Tell this project to use the session generated by the setup project
        storageState: 'playwright/.auth/user.json', 
      },
      // This tells Playwright: "Before running the 'chromium' project, 
      // make sure the 'setup' project completes successfully."
      dependencies: ['setup'], 
    },
    {
      name: 'firefox',
      use: { 
        ...devices['Desktop Firefox'],
        storageState: 'playwright/.auth/user.json',
      },
      dependencies: ['setup'], // Depends on the same setup
    },
  ],
});
```

## 4. Can this be done at the Test or Suite level?

**The short answer:** No, you **cannot** configure `globalSetup` or Project dependencies (`dependencies: ['setup']`) at the individual Test (`test()`) or Suite (`test.describe()`) level. 

**Why?**
- `globalSetup` and Setup Projects are **orchestration features** managed by the Playwright Test Runner *before* it even begins scheduling individual test files. They are strictly defined in `playwright.config.ts`.
- The config file is read and executed to determine *how* to spin up the workers, whereas tests are the *work* assigned to those workers.

**What you CAN do at the Test/Suite level instead:**
If you need setup logic strictly for a specific suite or a specific test, you must use Playwright's built-in hooks: `test.beforeAll` or `test.beforeEach`.

```typescript
// example.spec.ts
import { test } from '@playwright/test';

test.describe('Dashboard Suite', () => {
  // SUITE LEVEL SETUP
  test.beforeAll(async () => {
    // This runs once before any tests in this specific describe block start.
    // (Note: You have to launch the browser manually here or use API request context 
    // because the 'page' fixture is not available in beforeAll)
  });

  // TEST LEVEL SETUP
  test.beforeEach(async ({ page }) => {
    // This runs before EVERY single test in this suite.
    // Perfect for navigating to a starting page.
  });

  test('View Dashboard', async ({ page }) => {
    // Actual test code
  });
});
```

### Summary of Setup Hierarchies:
1. **`globalSetup`**: Runs **once per test run** (Config level).
2. **Setup Projects**: Runs **once per test run** but integrates into Playwright's reporting and allows fixtures (Config level).
3. **`test.beforeAll()`**: Runs **once per worker per file/suite** (Suite level).
4. **`test.beforeEach()`**: Runs **before every test** (Test level).

## 5. Can `globalSetup` be configured inside the `projects` array?

**No.** The `globalSetup` property is strictly a **root-level configuration** in Playwright. You cannot put `globalSetup` inside an individual project definition within the `projects` array. 

If you want a setup to be specific to a project, or defined within the `projects` array, you must use the **Setup Project (Project Dependencies)** approach (as shown in section 2).

**Invalid (Will NOT work):**
```typescript
export default defineConfig({
  projects: [
    {
      name: 'chromium',
      globalSetup: require.resolve('./global-setup'), // ❌ ERROR: Not allowed here!
    }
  ]
});
```

**Valid Approaches:**
1. **Root level (Runs for all projects):**
   ```typescript
   export default defineConfig({
     globalSetup: require.resolve('./global-setup'), // ✅ Allowed at the root level
     projects: [ ... ]
   });
   ```
2. **Inside Projects Array (Using Dependencies):**
   ```typescript
   export default defineConfig({
     projects: [
       { name: 'setup', testMatch: /.*\.setup\.ts/ }, // ✅ Project-based setup
       { 
         name: 'chromium', 
         dependencies: ['setup'] // ✅ Standard project relying on the setup
       }
     ]
   });
   ```

### Summary Rule of Thumb
- **If you are using a single standalone script** to do everything once: Use `globalSetup` at the **top** of the configuration.
- **If you are using Playwright fixtures** (`page`, `request`, etc.) in your setup: Use a Setup Project inside the **`projects` array**, and explicitly list it as a dependency for your browser projects.

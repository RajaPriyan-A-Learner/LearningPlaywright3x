# 180_IQ4 — Instance Identity and Independent State in the User Class

**File:** `21_chapter_Encapsulation/180_IQ4.js`

## Overview
This file demonstrates how classes act as factories creating multiple independent object instances (`u1`, `u2`), each retaining its own encapsulated instance state (`this.name`) while sharing common prototype behaviors (`greet()`).

---

## Main Concept
When multiple objects are instantiated from the same class:
1. **Independent Memory:** Each instance (`u1`, `u2`) has a separate memory block on the heap storing its own property values.
2. **Shared Behavior:** Prototype methods (like `greet()`) exist once in memory on `User.prototype`, and `this` resolves dynamically to the specific instance calling the method.

### Code Example

```javascript
class User {
  constructor(name) {
    this.name = name;
  }

  greet() {
    console.log("Hi, I am " + this.name);
  }
}

let u1 = new User("Alice");
let u2 = new User("Bob");

u1.greet(); // "Hi, I am Alice"
u2.greet(); // "Hi, I am Bob"
```

### Key Points
- Mutating `u1.name = "Alex"` has zero effect on `u2.name`.
- Methods defined directly inside the class body are automatically placed on `User.prototype`, optimizing memory allocation across hundreds or thousands of instances.
- Understanding instance identity is fundamental before advancing to class inheritance and polymorphism.

---

## Common Mistakes
- **Losing `this` context when passing methods as callbacks:** Passing `setTimeout(u1.greet, 1000)` detaches `greet` from `u1`, causing `this.name` to resolve to `undefined`. Use arrow functions `() => u1.greet()` or `.bind(u1)` to preserve context.
- **Modifying the prototype dynamically:** Adding properties to `User.prototype` affects all instances, whereas assigning to `this` inside constructor scopes values to that single instance.

---

## Summary
**Key Takeaway:** Classes guarantee that each object instance encapsulates its own unique state while sharing efficient prototype methods, preserving instance independence across the codebase.

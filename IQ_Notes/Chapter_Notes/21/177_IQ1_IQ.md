# 177_IQ1 — Private Instance Fields & Private Static Members in Test Automation

**File:** `21_chapter_Encapsulation/177_IQ1.js`

## Overview
This file demonstrates the advanced combination of private instance fields (`#status`) and private static properties (`static #count`) within a test automation domain class (`TestCase`). It shows how to track instance-level state alongside class-level shared counters securely.

---

## Main Concept
JavaScript classes support both instance-level and static-level private members:
1. **Private Instance Fields (`#status`):** Bound to individual instances. Each `TestCase` object tracks its own execution status ("not run", "PASSED", "FAILED").
2. **Private Static Fields (`static #count`):** Bound to the class constructor itself, shared across all instances, and invisible outside the class.
3. **Static Accessors (`static getCount`, `static setCount`):** Provide controlled access to inspect or modify class-wide counters.

### Code Example

```javascript
class TestCase {
    #status = "not run";
    static #count = 0;

    constructor(name) {
        this.name = name;
        TestCase.#count++;
    }

    run(pass) {
        this.#status = pass ? "PASSED" : "FAILED";
    }

    getStatus() {
        return this.#status;
    }

    static getCount() {
        return TestCase.#count;
    }

    static setCount(v) {
        TestCase.#count = v;
    }
}

const tc = new TestCase("login");
tc.run(true);
console.log(tc.getStatus()); // "PASSED"

new TestCase("login");
new TestCase("login");
new TestCase("login");
console.log(TestCase.getCount()); // 4
```

### Key Points
- `TestCase.#count` increments automatically every time the constructor executes via `new TestCase(...)`.
- External code cannot tamper with the count via `TestCase.#count = 0` or `tc.#count = 0`.
- In Playwright/test runners, this pattern is widely used for test case telemetry, run counts, suite execution counters, and isolated test status flags.

---

## Common Mistakes
- **Accessing static private fields via `this.#count` in static methods vs instance methods:** Inside instance methods, accessing `TestCase.#count` requires using the class name `TestCase.#count` rather than `this.#count`.
- **Calling static methods on instances:** Calling `tc.getCount()` results in `TypeError: tc.getCount is not a function`. Static methods must be invoked on the class `TestCase.getCount()`.

---

## Summary
**Key Takeaway:** Combining private instance fields with private static members allows classes to encapsulate both individual object state and shared class-wide metrics with complete protection from external tampering.

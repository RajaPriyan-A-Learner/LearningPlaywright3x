# 174_ — Private Fields and Data Encapsulation in JavaScript

**File:** `21_chapter_Encapsulation/174_.js`

## Overview
This file demonstrates the fundamental concepts of Encapsulation and Data Hiding in JavaScript classes using private class fields (`#`). It illustrates how private properties cannot be accessed directly from outside the class instance, and how controlled access is provided through explicit getter and setter methods.

---

## Main Concept
Encapsulation is one of the core Object-Oriented Programming (OOP) principles. It refers to bundling data (properties) and methods that operate on that data into a single unit (class) while restricting direct outside access to internal details.

In modern JavaScript (ES2022+):
1. **Private Field Declaration:** Fields prefixed with `#` (such as `#child1`, `#child2`) are private to the class scope.
2. **Access Control:** Attempting to read or write `#child1` outside the class throws a syntax error.
3. **Getter and Setter Methods:** `getChild1()` and `setChild1()` provide controlled read and write operations, allowing validation or formatting logic.

### Code Example

```javascript
class Person {
    // Hide your fields with #
    #child1;
    #child2;

    constructor(name, ch1, ch2) {
        this.name = name;
        this.#child1 = ch1;
        this.#child2 = ch2;
    }

    getChild1() {
        return this.#child1;
    }

    setChild1(changed_name) {
        this.#child1 = changed_name;
    }
}

let p = new Person("Pramod", "Vrad", "Jenny");
// console.log(p.#child1); // SyntaxError: Private field '#child1' must be declared in an enclosing class
console.log(p.getChild1()); // "Vrad"
p.setChild1("VIRAD");
console.log(p.getChild1()); // "VIRAD"
```

### Key Points
- Private fields must be pre-declared at the top of the class body before referencing them in the constructor.
- Private fields are not accessible via standard indexing (e.g., `p['#child1']` returns `undefined` and cannot read the private variable).
- Encapsulation prevents external code from corrupting internal object state.

---

## Common Mistakes
- **Accessing private fields directly on the instance:** Calling `p.#child1` triggers a compile-time `SyntaxError`.
- **Forgetting to declare private field upfront:** In JavaScript, unlike public properties, private properties cannot be dynamically added via `this.#field = val` without an upfront `#field;` declaration in the class body.

---

## Summary
**Key Takeaway:** JavaScript's `#` syntax enforces hard private encapsulation at the language level, ensuring internal state can only be accessed and modified via dedicated getter/setter methods.

# 178_IQ2 — Object Modeling and Encapsulation with the Bug Class

**File:** `21_chapter_Encapsulation/178_IQ2.js`

## Overview
This file demonstrates domain modeling in QA engineering by creating a `Bug` class that packages defect attributes (`title`, `severity`) together with behavior (`display()`) to format defect reports consistently.

---

## Main Concept
Encapsulation brings cohesive data and behavior together:
- Instead of passing loose primitive variables (e.g. `bugTitle1`, `bugSeverity1`) throughout test scripts, the `Bug` class provides a single, structured representation.
- The `display()` method standardizes how bug summaries are formatted across an entire test suite or logging framework.

### Code Example

```javascript
class Bug {
  constructor(title, severity) {
    this.title = title;
    this.severity = severity;
  }

  display() {
    console.log("[" + this.severity + "] " + this.title);
  }
}

let b1 = new Bug("Login crash", "Critical");
let b2 = new Bug("Typo in footer", "Low");

b1.display(); // "[Critical] Login crash"
b2.display(); // "[Low] Typo in footer"
```

### Key Points
- Every instance of `Bug` stores its own distinct properties while sharing the single `display()` method on `Bug.prototype`.
- Centralizing logging and formatting within class methods prevents code duplication across multiple test specs.
- Enhancements (such as color coding or timestamps) can be made in `display()` in one place and take effect immediately across all instances.

---

## Common Mistakes
- **String concatenation vs template literals:** Using template literals (e.g. `\`[${this.severity}] ${this.title}\``) is generally cleaner and less error-prone than string concatenation with `+`.
- **Missing input validation:** If severity is passed as `null` or an unexpected string, `display()` will still print it; in production QA frameworks, adding setter checks or constructor validation is best practice.

---

## Summary
**Key Takeaway:** The `Bug` class encapsulates defect state and formatting behavior into a reusable model, ensuring standardized defect reporting in test automation suites.

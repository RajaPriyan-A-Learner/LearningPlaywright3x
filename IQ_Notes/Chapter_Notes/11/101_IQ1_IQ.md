# 101_IQ1 — Interview Question: Var Shadowing

**File:** `11_chapter_Function/101_IQ1.js`

## Overview
This file presents a common interview question that tests your knowledge of how `var` behaves when declared both globally and inside a block.

## Main Concept
Because `var` is function-scoped (or globally scoped) and does NOT respect block scope (`{}`), declaring a `var` inside an `if` block with the same name as a global `var` simply overwrites the global variable.

### Code Example

```javascript
var a = "Pramod";

if (true) {
    console.log(a);    // Outputs: "Pramod"
    var a = "temp";    // Overwrites the global 'a'
    console.log(a);    // Outputs: "temp"
}

// If we added console.log(a) here, it would also output "temp"
```

### Key Points
- In the `if` block, `console.log(a)` runs before the inner `var a` is assigned, so it correctly accesses the outer `var a` which is "Pramod".
- The assignment `var a = "temp"` overwrites the single global instance of `a`.

---

## Common Mistakes
- **Assuming block scope for var:** Candidates often mistakenly say the first `console.log` will be `undefined` (thinking the inner `var` is hoisted locally) or that it creates a separate variable. `var` ignores the `if` block entirely.

---

## Summary
**Key Takeaway:** `var` ignores block scope; declaring a `var` inside a block with the same name as a global `var` simply modifies the existing global variable.

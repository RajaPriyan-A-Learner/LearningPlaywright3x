# 102_IQ2 — Interview Question: Let and TDZ Shadowing

**File:** `11_chapter_Function/102_IQ2.js`

## Overview
This file presents a highly deceptive interview question combining block scope, shadowing, and the Temporal Dead Zone (TDZ) using `let`.

## Main Concept
When you declare a `let` variable inside a block, it immediately shadows any outer variable with the same name for that entire block. However, if you try to use the variable before its local initialization line, it triggers a TDZ ReferenceError instead of falling back to the outer variable.

### Code Example

```javascript
let a = 10;
console.log(a); // Outputs: 10

if (true) { 
    // console.log(a); // ❌ ReferenceError: Cannot access 'a' before initialization
    let a = 20;
}
```

### Key Points
- The inner `let a = 20;` tells the JS engine: "For this `if` block, `a` refers to me."
- The `console.log(a)` inside the block runs *before* `a` is initialized.
- It does not "look up" to find the global `a = 10`; it finds the local `a` in its TDZ and crashes.

---

## Common Mistakes
- **Thinking it will print 10:** Candidates often assume that if the local `a` isn't ready yet, JS will just use the global `a` = 10. The block scope intercepts the lookup entirely.

---

## Summary
**Key Takeaway:** A block-scoped `let` or `const` shadows outer variables of the same name for the entire block, causing a Temporal Dead Zone error if accessed before initialization.

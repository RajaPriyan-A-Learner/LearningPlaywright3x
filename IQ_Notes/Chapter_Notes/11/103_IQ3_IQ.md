# 103_IQ3 — Interview Question: Const Immutability and TDZ

**File:** `11_chapter_Function/103_IQ3.js`

## Overview
This file explores common interview questions regarding the `const` keyword, covering both its Temporal Dead Zone and its strict rule against reassignment.

## Main Concept
`const` behaves exactly like `let` regarding block scope and the Temporal Dead Zone (TDZ). The crucial difference is that a variable declared with `const` must be initialized immediately and cannot be reassigned a new value later.

### Code Example

```javascript
// TDZ for const
// console.log(MAX_RETRIES); // ❌ ReferenceError (TDZ)
const MAX_RETRIES = 3;
// MAX_RETRIES = 4;          // ❌ TypeError: Assignment to constant variable.

const score = 100;
// score = score + 10;       // ❌ TypeError

const prod_api_url = "https://app.example.com/#login";
const qa_api_url = "https://qa.example.com/#login";

let abc = "anil";
console.log(abc);            // ✅ Outputs: "anil"
```

### Key Points
- `const` requires an initial value. (`const x;` is a SyntaxError).
- Attempting to assign a new value to a `const` throws a TypeError.
- Just like `let`, accessing a `const` before its declaration throws a ReferenceError due to the TDZ.

---

## Common Mistakes
- **Reassigning const in calculations:** `score = score + 10` is an assignment operation. You cannot do this with `const`.
- **Assuming const is fully read-only data:** While the variable binding is immutable, the *contents* of objects and arrays assigned to a `const` can still be changed.

---

## Summary
**Key Takeaway:** `const` provides block-scoped variables that cannot be reassigned; they are also subject to the Temporal Dead Zone before initialization.

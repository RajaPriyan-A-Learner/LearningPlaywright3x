# 185_IQ3 — Polymorphic Test Execution and the Strategy Pattern

**File:** `22_chapter_Inheritance/Single Inheritance/185_IQ3.js`

## Overview
This file demonstrates **Subtype Polymorphism** in JavaScript. By deriving multiple specialized test runners (`UnitTest`, `APITest`, `E2ETest`) from a common base class (`TestCase`), a single runner loop can uniformly iterate through an array of heterogeneous test instances and trigger their individual `execute()` implementations.

---

## Main Concept
Polymorphism ("many forms") allows different classes to be treated through a single uniform interface.

### Heterogeneous Collections and Unified Invocation
- A base class `TestCase` defines the interface contract `execute()`.
- Derived subclasses (`UnitTest`, `APITest`, `E2ETest`) implement custom test execution logic.
- An array containing varied test types can be iterated uniformly with `tests.forEach(test => test.execute())`.

### Code Example

```javascript
class TestCase {
    execute() {
        console.log("Running generic test");
    }
}

class UnitTest extends TestCase {
    execute() {
        console.log("Running unit test — checking one function");
    }
}

class APITest extends TestCase {
    execute() {
        console.log("Running API test — sending HTTP request");
    }
}

class E2ETest extends TestCase {
    execute() {
        console.log("Running E2E test — opening browser");
    }
}

let tests = [new UnitTest(), new APITest(), new E2ETest()];
tests.forEach(function (test) {
    test.execute();
});
```

### Key Points
- Open/Closed Principle (SOLID): You can add new test types (e.g. `PerformanceTest`) without modifying the test runner loop.
- The runtime automatically dispatches `execute()` to the appropriate class implementation based on the actual instance type.
- This pattern forms the core execution loop of modern test runners like Jest, Mocha, and Playwright Test.

---

## Common Mistakes
- **Using `switch` statements instead of polymorphism:** Checking `if (type === 'unit') ... else if (type === 'api')` violates OOP open-closed design. Polymorphism replaces branching logic with clean inheritance hierarchies.
- **Inconsistent method signatures:** If one subclass defines `execute(data)` with required parameters while others do not, uniform iteration breaks.

---

## Summary
**Key Takeaway:** Polymorphism enables uniform execution across different class hierarchies, allowing test suites to orchestrate diverse test types through a shared `execute()` interface.

# 184_IQ2 — Method Extension via `super` in Test Lifecycle Hooks

**File:** `22_chapter_Inheritance/Single Inheritance/184_IQ2.js`

## Overview
This file demonstrates **Method Extension** (partial overriding) using `super.methodName()`. Instead of completely replacing parent methods, the child class `UITest` combines parent setup/teardown logic with its own specialized steps (maximizing windows, capturing screenshots).

---

## Main Concept
In real-world test automation, test lifecycles typically require common base setup (e.g. launching browsers) followed by test-specific enhancements (e.g. maximizing viewport, setting auth cookies).

### Pre-execution vs Post-execution with `super`
1. **Extending Setup:** Calling `super.setup()` first ensures the base browser opens before UI-specific configurations are applied.
2. **Extending Teardown:** Capturing screenshots before calling `super.teardown()` ensures evidence is collected while the browser is still alive.

### Code Example

```javascript
class BaseTest {
    constructor() {
        console.log("Parent!");
    }
    setup() {
        console.log("Base: open browser");
    }
    teardown() {
        console.log("Base: close browser");
    }
}

class UITest extends BaseTest {
    constructor() {
        super(); // Invokes BaseTest constructor
    }
    setup() {
        super.setup(); // Calls parent setup first
        console.log("UI: maximize window");
    }

    teardown() {
        console.log("UI: take screenshot");
        super.teardown(); // Calls parent teardown last
    }
}
```

### Key Points
- Order of execution matters: In teardown, taking a screenshot (`UI: take screenshot`) MUST occur before closing the browser (`Base: close browser`).
- `super.setup()` maintains DRY (Don't Repeat Yourself) architecture by keeping common browser management code in `BaseTest`.
- Both `super()` (constructor) and `super.methodName()` preserve the dynamic `this` reference bound to the `UITest` instance.

---

## Common Mistakes
- **Closing resources before capturing artifacts:** If `super.teardown()` were called before `take screenshot`, the browser would be closed and screenshot capture would fail.
- **Forgetting `super()` in the derived constructor:** If you define a `constructor()` in a derived class, omitting `super()` throws a `ReferenceError` when `this` is initialized.

---

## Summary
**Key Takeaway:** Using `super.methodName()` allows child classes to augment rather than completely replace parent lifecycle methods, coordinating setup and teardown tasks in the correct execution order.

# 169_IQ2 — Private Fields (#) and Hard Encapsulation for Sensitive Data

**File:** `20_chapter_Class_objects/20_02_Public_private/169_IQ2.js`

## Overview
This file explores the difference between public class properties and modern JavaScript private class fields declared with the `#` prefix. Using a `Credentials` model, it demonstrates how sensitive information (like API tokens and passwords) can be safely encapsulated so that it is accessible only from methods within the class body and completely hidden from outside consumers.

---

## Main Concept

JavaScript class fields can be declared as **Public** or **Private**:
1. **Public Fields:** Declared without `#` (e.g., `user`). They become accessible properties on any instance of the class (`cred.user`).
2. **Private Fields (`#`):** Declared with the `#` prefix inside the class body before the constructor (e.g., `#apiKey`). They are lexically scoped to the class body and enforced at the engine level.
3. **Encapsulated Access:** Private fields can only be read or written by instance methods declared within that exact class definition (e.g., `pramodgetAuthHeader()`).

### Code Example

```javascript
class Credentials {
    // Private Field Declaration (Hard Encapsulation)
    #apiKey; 
    user; // Public Field

    constructor(user, key) {
        this.user = user;        // Accessible everywhere
        this.#apiKey = key;      // Enforced private state
    }

    // Method with internal access to private fields
    pramodgetAuthHeader() {
        return "Bearer " + this.#apiKey;
    }
}

let cred = new Credentials("admin", "secret_key_1234");

console.log(cred.user); // "admin" (Public)
console.log(cred.pramodgetAuthHeader()); // "Bearer secret_key_1234"

// Attempting external access:
// console.log(cred.apiKey);  // undefined (No public property 'apiKey')
// console.log(cred.#apiKey); // Throws SyntaxError: Private field '#apiKey' must be declared in an enclosing class
```

### Key Points
- Unlike the older convention of using underscores (e.g., `_apiKey`), `#apiKey` is a true language-level private identifier.
- Private fields cannot be accessed dynamically via bracket notation (`cred['#apiKey']` returns `undefined`).
- Private fields are not enumerated by `Object.keys(cred)`, `Object.entries()`, or `for...in` loops, preventing accidental data leaks in JSON serialization.

---

## Common Mistakes
- **Accessing `#` fields outside the class:** Referencing `cred.#apiKey` outside the class throws a compile-time/syntax error.
- **Forgetting to declare private field upfront:** Unlike public fields which can be assigned ad-hoc on `this`, private fields MUST be declared in the class body prior to using `this.#field` in constructor or methods.

---

## Summary
**Key Takeaway:** The `#` syntax introduces true private fields in JavaScript classes, completely concealing sensitive data like authentication keys from external access while permitting internal class methods to safely operate on them.

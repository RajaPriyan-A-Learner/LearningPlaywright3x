# 173_IQ1 — Public Field Declarations, Outer Scope Closures, and Constructor Flow

**File:** `20_chapter_Class_objects/20_03_Static/173_IQ1.js`

## Overview
This file explores public class field declarations (`b;`), how constructors interact with outer lexical scopes (such as global variables `let a = 10`), and the step-by-step property initialization flow that occurs every time a class object is instantiated.

---

## Main Concept

Modern JavaScript class syntax supports direct public field declarations at the top of the class body:
1. **Public Class Field (`b;`):** Declaring a property outside the constructor creates that property on the instance with an initial value of `undefined` before the constructor body executes.
2. **Lexical Scope Resolution:** The constructor code has access to its enclosing lexical scope, meaning variables declared outside the class (like `let a = 10`) are accessible via standard closure/scope resolution rules.
3. **Execution on Every Instantiation:** Every `new Car()` invocation logs the scoped variable `a` and sets `this.b = 10`.

### Code Example

```javascript
let a = 10; // Outer lexical scope variable

class Car {
    b; // Public field declaration (initialized to undefined before constructor)

    constructor() {
        console.log(a);  // Reads outer variable 'a' (10)
        this.b = 10;     // Initializes instance property 'b'
    }
}

// Instantiating first object
let obj = new Car(); 
// Output: 10
// obj is { b: 10 }

// Instantiating second object
let obj2 = new Car();
// Output: 10
// obj2 is { b: 10 }
```

### Key Points
- Public field declarations improve class readability by documenting all object properties upfront at the class definition level.
- Class fields can also have default initializer expressions (e.g., `b = 10;`), which run before constructor logic.
- Constructors retain closure access to variables defined in their module or file scope, making dependency injection and outer configuration references seamless.

---

## Common Mistakes
- **Shadowing outer variables unintentionally:** Declaring `let a = ...` inside the constructor or having a property `this.a` while expecting it to update the outer variable `a`.
- **Misunderstanding field initialization order:** Class fields are initialized in order of appearance before the constructor body runs.

---

## Summary
**Key Takeaway:** Public field declarations define instance properties explicitly on the class body, and constructor methods seamlessly access outer lexical variables during object instantiation.

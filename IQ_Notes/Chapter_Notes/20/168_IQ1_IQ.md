# 168_IQ1 — API Client Design and Environment URL Configuration

**File:** `20_chapter_Class_objects/20_02_Public_private/168_IQ1.js`

## Overview
This file demonstrates the implementation of a reusable `APIClient` class in JavaScript. It shows how class instances can encapsulate environment-specific configurations (such as base URLs for staging vs. production environments) while exposing unified request builder methods like `get(path)`.

---

## Main Concept

In automated API testing and full-stack web applications, creating modular HTTP client wrappers is standard practice.

### Key Concepts:
1. **Configurable Base State:** Storing `this.baseURL` allows each `APIClient` instance to target a distinct backend environment without altering request logic.
2. **Path Resolution:** The `get(path)` instance method concats the instance's base URL with the relative endpoint resource path.
3. **Environment Separation:** Instantiating `staging` and `prod` clients ensures complete isolation between test environments.

### Code Example

```javascript
class APIClient {
    constructor(baseURL) {
        this.baseURL = baseURL;
    }

    get(path) {
        return this.baseURL + path;
    }
}

// Creating environment-specific API clients
let staging = new APIClient("https://staging.api.com");
let prod = new APIClient("https://prod.api.com");

console.log(staging.get("/users"));      // "https://staging.api.com/users"
console.log(prod.get("/prod/users"));    // "https://prod.api.com/prod/users"
```

### Key Points
- By encapsulating the `baseURL` inside the instance, test scripts never hardcode full URLs, making test suites portable across dev, test, staging, and production environments.
- In modern Playwright or Axios frameworks, API client classes wrap underlying `request.get()` and `request.post()` calls with custom authentication headers and assertion checks.
- Dynamic paths can be safely combined using helper methods, `new URL(path, this.baseURL)`, or template literals.

---

## Common Mistakes
- **Trailing / Leading Slash Conflicts:** Simple string concatenation (`this.baseURL + path`) can lead to double slashes (`https://example.com//users`) if `baseURL` has a trailing slash and `path` has a leading slash. Using `new URL(path, this.baseURL).toString()` avoids this.
- **Hardcoding credentials or URLs:** Hardcoding environment details inside method bodies rather than injecting them via constructor parameters.

---

## Summary
**Key Takeaway:** An `APIClient` class encapsulates environment configurations like `baseURL`, allowing clean endpoint resolution and seamless environment switching across automated test suites.

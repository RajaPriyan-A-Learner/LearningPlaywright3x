Core Concepts Extracted

📜 Function Declaration

The standard way to declare a function. The entire function body is hoisted, meaning it can be called before it is defined in the code.

Declaration
sayHello("John"); // Works! Hoisted.

function sayHello(name) {
    return "Hello " + name;
}

🏹 Arrow Functions

Modern ES6 syntax. They are shorter and do not bind their own `this` keyword, making them perfect for callbacks.

Arrow Syntax
const add = (a, b) => a + b;

// Parentheses optional for single arg
const square = x => x * x;

⚙️ The Temporal Dead Zone (TDZ)

When using `let` and `const`, the variables are hoisted but remain uninitialized. Accessing them in this zone throws a ReferenceError.

TDZ
console.log(a); // undefined (var)
console.log(b); // ReferenceError! (TDZ)

var a = 10;
let b = 20;

🧳 Rest & Spread Operators

`...` can be used to gather infinite arguments into an array (Rest) or unpack an array into individual variables (Spread).

Rest Parameters
function sum(...numbers) {
    return numbers.reduce((a, b) => a+b);
}
sum(1, 2, 3, 4); // 10

Real World & Common Mistakes

🛠️ Real-World Use Case

Immediately Invoked Function Expressions (IIFEs): Used heavily before ES6 Modules to create private scopes and avoid polluting the global window object.

Practical Example
(function() {
    // This config is hidden from window!
    const _apiKey = "12345"; 
    console.log("App Initialized");
})();

❌ Common Developer Mistake

Var Scope Leakage: `var` is function-scoped, not block-scoped. Declaring it inside an `if` block or `for` loop causes it to leak out into the entire function!

Common Mistake
if (true) {
    var leaked = "I escaped!";
    let secure = "I am safe.";
}

console.log(leaked); // Prints! 💥
console.log(secure); // ReferenceError ✅
Zero to Hero

Interview Preparation

Q1: What is Hoisting?
The JavaScript engine's behavior of moving variable and function declarations to the top of the current scope during the compilation phase, before execution begins. Functions are hoisted completely, `var` is hoisted as `undefined`, and `let/const` are hoisted into the TDZ.
Q2: What is the output?
let x = 1;
if (true) {
    console.log(x);
    let x = 2;
}
Answer: ReferenceError. The `let x = 2` inside the block shadows the global `x` and is hoisted to the top of the block. The `console.log(x)` hits the local `x` while it's still in the Temporal Dead Zone.
Q3: First-Class Functions vs Higher-Order Functions?
First-Class: The concept that functions in JS are just values (they can be assigned to variables or passed around).
Higher-Order: A function that either takes another function as an argument or returns a function.

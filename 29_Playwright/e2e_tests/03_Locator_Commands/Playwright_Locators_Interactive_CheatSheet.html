Deep-Dive Syntax Reference
Accessibility First

page.getByRole(role, options)

Queries the browser's computed ARIA accessibility tree. The gold standard for resilient automation.

await page.getByRole('textbox', { name: 'Email', exact: true }).fill('admin@vwo.com');
Roles: button, link, textbox, checkbox, heading, dialog, alert, tab, combobox
Form Association

page.getByLabel(text, options)

Locates form controls via <label for>, aria-label, or aria-labelledby.

await page.getByLabel('Password', { exact: true }).fill('secret123');
Matches accessible label bindings directly.
Testing Contract

page.getByTestId(testId)

Explicit contract between Dev and QA. Immune to all HTML and CSS restyling.

await page.getByTestId('submit-order-button').click();
Configurable attribute in playwright.config.ts (default: data-testid)
Sub-Tree Filtering

.filter({ has, hasText })

Filters existing locators by nested child elements or text without string concatenation.

const userRow = page.getByRole('row').filter({ has: page.getByText('admin@vwo.com') });
await userRow.getByRole('button', { name: 'Delete' }).click();

Descendant, Child & Siblings

The Mechanics of Computed Accessible Name

When Playwright runs page.getByRole('button', { name: 'Submit' }), it does not conduct a simplistic string search. It invokes the browser's native accessibility calculation:

  1. Inspects aria-labelledby ID references.
  2. Evaluates explicit aria-label strings.
  3. Reads host language bindings (such as <label for="id"> or form control placeholder).
  4. Recursively computes visible text nodes within the element's subtree.
  5. Falls back to title or alt attribute values.

Why Playwright Locators Never Go "Stale"

In legacy frameworks (Selenium), an element lookup returns a static remote reference pointer. When a modern framework (React, Vue, Svelte) modifies state and re-renders the component, that pointer points to a detached node, throwing the dreaded StaleElementReferenceException.

Playwright locators are lazy recipes. They do not store pointers in memory; they re-evaluate the locator recipe at the exact microsecond an interaction is dispatched. Re-renders are absorbed seamlessly without test failures.

Conclusion: The Hierarchy of Locator Reliability

Testing against the accessibility tree ensures that tests only fail when a feature is truly broken for end users. If an engineer refactors CSS classes from BEM to Tailwind, or swaps a native <button> for a custom accessible component, Playwright tests continue to pass with zero modifications.

Core Concepts Extracted

🔄 From Promises to Async/Await

Async/Await is syntactic sugar over Promises. An `async` function always returns a Promise. The `await` keyword pauses the execution of the async function until the Promise settles.

148_Async_Await.js 
// Before: Promise Chaining
getToken().then(function(token) {
    return getUser(token);
}).then(function(user) {
    console.log(user);
});

// After: Async/Await
async function run() {
    let token = await getToken();
    let user = await getUser(token);
}

🛡️ Error Handling (Try/Catch)

Instead of `.catch()`, Async/Await lets you use standard JavaScript `try/catch/finally` blocks, making error handling identical to synchronous code.

150_AA.js 
async function testAPI() {
    try {
        let result = await Promise.reject("503 Error");
    } catch (error) {
        console.log('Caught:', error);
    } finally {
        console.log("Cleanup!");
    }
}

⚡ Sequential vs Parallel

Using `await` consecutively executes sequentially. To run tasks in parallel and wait for all, combine `await` with `Promise.all()`.

153_Seq & 154_Parallel.js 
// Sequential (Slow)
let r1 = await apiCall("Login");
let r2 = await apiCall("Dashboard");

// Parallel (Fast)
let [r1, r2] = await Promise.all([
    apiCall("Login"),
    apiCall("Dashboard")
]);

🎯 Real QA Use Case: Flaky APIs

Testing unstable endpoints requires retry mechanisms. Async/await makes implementing a Retry Pattern incredibly straightforward using a `for` loop.

155_API_Flaky.js 
async function retry(operation, max) {
    for (let i = 1; i <= max; i++) {
        try {
            return await operation();
        } catch (error) {
            if (i === max) throw error;
        }
    }
}

Q1: Can you use `await` outside of an `async` function?
Historically, no. `await` was strictly tied to `async` functions. However, modern JavaScript (ES2022+) supports Top-Level Await in ES modules, allowing `await` at the root level of a module.
Q2: What is the output of this Event Loop question?
console.log("A");
async function test() {
    console.log("B");
    await Promise.resolve();
    console.log("C");
}
test();
console.log("D");
Output: A, B, D, C.
Explanation: "A" is synchronous. `test()` is called, logging "B" synchronously. The `await` pushes the rest of `test()` ("C") to the Microtask Queue. Synchronous code continues, logging "D". Finally, the call stack is empty, so the Microtask Queue is processed, logging "C".
Q3: Does Async/Await run code in parallel?
No, Javascript remains single-threaded. Async/Await is just a way to handle asynchronous execution without blocking the main thread. To achieve parallel-like concurrent fetching, you must combine it with Promise.all().

🔒 What is a Closure?

A closure is a function that remembers the variables from its lexical scope even after the outer function has returned. It forms a persistent memory bubble.

Basic Closure
function makeCounter() {
    let count = 0;
    return function() {
        count++;
        return count;
    };
}
const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2

🛡️ Encapsulation

Closures are widely used to emulate private variables. The `count` variable above cannot be accessed or modified directly from the outside; it is perfectly secure.

Private State
// count is hidden from the global scope!
console.log(count); // ReferenceError
counter.count = 99; // Doesn't work

🏭 Factory Functions

Closures allow you to generate specialized functions on the fly, like creating customized greeting functions or specific configuration handlers.

Factories
function greetConfig(greeting) {
    return function(name) {
        console.log(`${greeting}, ${name}`);
    }
}
const sayHi = greetConfig("Hi");
sayHi("John"); // Hi, John

🗑️ Memory Leaks

Because closures maintain references to their outer environments, the Garbage Collector cannot clear those variables as long as the inner function is accessible.

Memory Retention
function heavyProcess() {
    const hugeArray = new Array(1000000);
    return function() {
        console.log(hugeArray[0]);
    }
}
// hugeArray stays in memory forever!
const leak = heavyProcess();
Practical Application

Real World & Common Mistakes

🛠️ Real-World Use Case

Rate Limiters & API Factoring: You can create specialized factory functions that spawn functions with built-in memory state without using Classes.

Practical Example
function createRateLimiter(limit) {
    let calls = 0;
    return function() {
        calls++;
        return calls <= limit;
    }
}
const canCall = createRateLimiter(2);
canCall(); // true
canCall(); // true
canCall(); // false (limit hit!)

❌ Common Developer Mistake

The Loop `var` Bug: Using `var` inside a loop that creates closures leads to all closures sharing the exact same variable reference, usually causing bugs!

Common Mistake
// MISTAKE: All functions print "3"
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
} 

// CORRECT: Use 'let' to bind a new scope
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
}
Zero to Hero

Interview Preparation

Q1: Explain Lexical Scoping.
Lexical scoping means that a variable's scope is determined statically by its physical location in the source code. Nested functions have access to variables declared in their outer scope.
Q2: How do you create private variables in JavaScript?
Before ES2022 private class fields (`#`), closures were the standard way. You wrap a variable inside an outer function and return an object with methods that interact with it, preventing direct outside access.
Q3: Do Closures cause Memory Leaks?
Yes, they can! Because closures maintain references to their outer lexical environment, the Garbage Collector cannot clear those outer variables from memory as long as the inner function is still accessible. Careless use in large applications can lead to memory leaks.
